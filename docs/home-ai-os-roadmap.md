# HomeMind 家庭 AI OS 演进目标

## 1. 愿景

HomeMind 的长期目标是成为运行在 Windows、Linux、macOS、NAS 和家庭边缘设备之上的**家庭 AI 操作层**：统一管理家庭成员、智能体、设备、数据、任务、自动化与外部服务，让用户通过自然语言或确定性规则安全地感知、决策和执行。

HomeMind 不以替代传统操作系统内核、驱动或系统服务为目标。“OS”在本文中指面向家庭场景的资源、能力、权限、事件和应用控制平面。

## 2. 核心原则

- **本地优先**：家庭数据和关键自动化应尽可能在本地运行，云端能力按需使用。
- **确定性执行**：LLM 负责理解、规划和建议；确定性引擎负责授权、执行、重试和恢复。
- **最小权限**：用户、Agent、Skill、Plugin 和设备仅获得完成任务所需的权限。
- **可解释、可追溯**：敏感操作必须能回答谁发起、为何执行、访问了什么以及结果如何。
- **离线可用**：断网或云服务不可用时，家庭关键能力仍可工作。
- **渐进演进**：复用现有家庭、设备、权限、事件、任务、事务和智能家居模块，不建设传统 OS 内核。

## 3. P0：形成家庭 AI OS 的核心闭环

### 3.1 统一资源模型

目标：为家庭、成员、设备、资产、记忆、知识、任务、日历和自动化建立一致的资源表达。

需要补齐：

- 全局稳定的资源 ID、资源类型和版本化元数据。
- 所有者、家庭归属、可见范围和生命周期状态。
- 可查询的资源关系，例如“成员拥有设备”“资产属于相册”“任务涉及成员”。
- 统一的资源定位方式，例如 `homemind://devices/{id}`。
- 统一搜索、订阅、审计和权限检查入口。

验收标准：

- 任一核心资源都能通过统一 ID 定位并获得类型、归属和权限信息。
- 跨领域关系无需调用方了解各模块的数据库结构。
- 新资源类型可以接入统一搜索、审计和授权流程。

### 3.2 统一能力模型

目标：用与厂商无关的能力描述设备、平台和外部服务可以执行的动作。

需要补齐：

- 标准能力命名，如 `switch.on`、`climate.set_temperature`、`calendar.create_event`。
- 输入、输出和错误的版本化 Schema。
- 风险等级、确认策略和所需权限。
- 幂等键、超时、取消、重试和补偿语义。
- 执行结果与真实状态回读，区分“已受理”和“已生效”。

验收标准：

- 同一种能力可由不同厂商设备或 Connector 实现。
- Agent 和自动化引擎只依赖标准能力，不直接依赖厂商 API。
- 高风险能力无法绕过授权和确认流程。

### 3.3 细粒度权限与身份代理

目标：明确谁可以以谁的身份，对什么资源执行什么动作。

需要补齐：

- 用户—角色—资源—动作四维授权。
- Agent、Skill、Plugin 和 Connector 的权限声明。
- 一次性、限时、会话级和长期授权。
- 管理员、成人、儿童、老人和访客等家庭角色策略。
- 授权撤销即时生效，敏感访问全部进入审计记录。
- 明确显示执行主体、授权主体和最终责任人。

验收标准：

- 每次敏感调用都能解释授权来源。
- 私有资源不能因同属一个家庭而被默认共享。
- 权限撤销后，后台任务和离线设备也无法继续使用旧授权。

### 3.4 统一事件系统

目标：让设备、数据、任务和家庭活动通过稳定事件契约协作。

需要补齐：

- 统一事件 Envelope、事件 ID、来源、时间、主体和 Schema 版本。
- 订阅、过滤、持久化、去重、顺序和重放能力。
- 事件级权限过滤和敏感字段脱敏。
- 边缘节点离线后的补发与冲突处理。
- 标准事件目录，如 `device.offline`、`asset.imported`、`task.overdue`。

验收标准：

- 业务模块不通过私有回调形成不可追踪的跨域耦合。
- 消费者重启后可安全恢复处理，不重复产生副作用。
- 未授权订阅者无法从事件中推断敏感家庭信息。

### 3.5 确定性自动化引擎

目标：支持“事件 + 条件 + 动作 + 状态”的可靠家庭自动化。

需要补齐：

- 时间、事件、状态和地理围栏触发器。
- 条件、分支、等待、延迟和人工确认节点。
- 去重、防循环、超时、重试和补偿。
- 模拟运行、版本管理、启停和完整执行历史。
- 自然语言可以生成或修改规则，但落盘格式必须可验证、可审计。

验收标准：

- 自动化在不调用 LLM 的情况下也能按已保存规则执行。
- 相同事件重复投递不会重复产生危险副作用。
- 用户能在启用前看到触发条件、权限需求和预期动作。

## 4. P1：形成应用与设备生态

### 4.1 统一应用模型

明确平台概念边界：

| 类型 | 职责 |
| --- | --- |
| Skill | 模型遵循的工作方法和知识 |
| Tool | 单个可调用能力 |
| Connector | 外部账号或服务连接 |
| Plugin / App | 可安装的软件包，可组合工具、页面和后台任务 |
| Agent | 具有身份、记忆和权限的执行主体 |
| Automation | 确定性的触发与执行流程 |

App Manifest 至少声明名称、版本、发行者、权限、工具、页面、后台任务、数据范围、兼容平台、迁移脚本和签名信息。

验收标准：应用可以被安全地发现、安装、启用、停用、升级、回滚和卸载，卸载时明确处理其数据。

### 4.2 隔离应用运行时

需要补齐：

- 独立进程或容器隔离。
- 文件、网络、密钥和设备能力的最小授权。
- CPU、内存、运行时间和并发限制。
- 工具调用审批、熔断和紧急终止。
- 密钥按调用注入，不写入 Agent 工作区或日志。

验收标准：第三方应用默认不能读取主机文件、家庭私有数据或任意访问网络。

### 4.3 完整设备生命周期

需要补齐：

- 安全配对、设备身份、证书轮换和撤销。
- 在线、离线、休眠、故障和最后同步状态。
- 能力发现、远程配置、OTA 更新和恢复出厂。
- 设备转让、移除和数据清理。
- 弱网、断网下的本地执行与恢复同步。

验收标准：设备丢失、被盗、转让或长期离线时都有明确且可验证的安全处置流程。

### 4.4 局域网发现与云—边—端调度

需要补齐：

- 局域网设备发现和可信配对。
- Home Assistant、Matter 等标准适配层。
- NAS、PC、手机等节点的能力与负载登记。
- 根据隐私、延迟、成本和可用性选择执行节点。
- 本地与云端推理的显式路由策略。

验收标准：关键家庭自动化在互联网不可用时仍可运行，恢复联网后能安全同步状态。

## 5. P2：提高可信度与日常可用性

### 5.1 家庭状态图

维护统一的家庭当前状态，并为每项状态记录来源、更新时间和置信度。Agent 必须区分已确认、推测、过期和未知状态。

### 5.2 活动与解释中心

统一展示发起者、决策 Agent、授权依据、数据访问、执行步骤、结果和撤销入口，避免信息散落在聊天、任务、设备和日志页面。

### 5.3 可恢复事务

跨设备和跨服务操作需要持久化状态机、旧状态记录、用户取消、超时恢复、失败补偿，以及服务重启后的续跑能力。

### 5.4 注意力与通知管理

支持优先级、勿扰时间、消息合并、多通道降级、已读状态、紧急升级和成员级隐私过滤。

### 5.5 备份与灾难恢复

支持加密增量备份、恢复演练、单资源恢复、家庭迁移、数据导出和删除，以及数据库和版本升级场景的恢复验证。

### 5.6 系统健康与可观测性

提供面向普通用户的设备、服务、任务、存储、数据库、模型成本和自动化健康视图，并能导出经过隐私处理的诊断包。

## 6. 推荐实施顺序

1. 统一资源 ID、资源类型和关系表达。
2. 在现有智能家居命令目录基础上建立统一能力契约。
3. 将细粒度权限和审计接入资源、能力与后台任务。
4. 统一家庭事件契约，并实现持久化、去重和重放。
5. 建立确定性自动化引擎。
6. 深化设备状态、离线执行和可恢复事务。
7. 定义 App Manifest 和隔离运行时。
8. 建设应用分发、边缘节点调度和家庭状态图。

任何阶段都应先完成纵向闭环，再扩展资源类型或厂商适配。例如，先让一种灯具从发现、授权、状态同步、自动化到审计完整可用，再扩大设备覆盖面。

## 7. 阶段性里程碑

### M1：统一控制平面

- 核心资源拥有统一身份和关系模型。
- 设备和服务通过标准能力被调用。
- 所有敏感调用经过统一授权和审计。

### M2：可靠家庭自动化

- 标准事件可以持久化、重放和去重。
- 自动化不依赖 LLM 在线执行。
- 跨设备操作可以取消、恢复和补偿。

### M3：安全应用平台

- 第三方 App 具备 Manifest、权限声明和隔离运行环境。
- 安装、升级、回滚和卸载形成完整生命周期。
- 用户能理解并控制应用访问的数据和能力。

### M4：家庭 AI 操作层

- 家庭关键能力支持离线运行。
- 系统能够在本地、边缘和云端之间选择执行位置。
- Agent 基于带来源和置信度的家庭状态进行建议或操作。
- 用户可以通过对话管理资源、权限、设备、应用和自动化，同时保留确定性控制入口。

## 8. 非目标

- 不开发操作系统内核、硬件驱动或通用窗口管理器。
- 不以功能数量代替统一平台契约。
- 不允许 LLM 绕过权限、确认或确定性执行引擎直接实施高风险操作。
- 不为追求“全自动”牺牲用户知情权、撤销能力和家庭隐私。
