# HomeMind 项目使用与接入指南

> 面向准备安装、使用或集成 HomeMind 的家庭管理员、普通成员和开发者。
>
> HomeMind 是构建在 Octop 运行时之上的自托管家庭 AI 平台。`homemind` 负责家庭、设备、资产、日历、任务和家庭记忆等能力；专家、模型、连接器、通道、知识库和自动化复用 Octop 的运行时与管理能力。

## 1. 先理解 HomeMind

### 1.1 一次请求如何执行

```text
网页 / 桌面端 / CLI / 消息平台
                │
                ▼
          用户身份与家庭权限
                │
                ▼
        专家或专家团队理解任务
                │
      ┌─────────┼─────────┐
      ▼         ▼         ▼
    技能      知识库     连接器 / 设备
      └─────────┼─────────┘
                ▼
       回复、文件、任务或待审批操作
                │
                ▼
      对话历史与可控家庭记忆
```

用户只需要描述目标，例如：

> 读取家庭日历和天气，提醒大家明天的安排；如果下雨，提前打开玄关灯。

HomeMind 会在当前用户权限内选择专家，并按需调用日历、天气和 Home Assistant。设备写操作是否立即执行，取决于设备风险等级和家庭审批策略。

### 1.2 核心概念

| 概念 | 用途 | 示例 |
|------|------|------|
| 家庭 | 成员、共享空间与权限的边界 | “小满一家” |
| 专家 | 有独立人设、模型、技能和工作区的 AI | PPT 演示专家、学习助手 |
| 专家团队 | 由协调者调度多个专家完成复杂任务 | 产品经理 + 数据分析 + PPT 专家 |
| 技能 | 告诉专家如何完成某类工作 | PPTX、PDF、代码审查 |
| 知识库 | 提供可检索的私有资料 | 家庭手册、课程资料、项目文档 |
| 连接器 | 授权专家访问外部服务 | 邮箱、文档、网盘、Notion |
| 通道 | 从外部聊天平台与专家对话 | 飞书、企业微信、Discord |
| 家庭设备 | 运行设备 Runtime 或经 Home Assistant 接入的设备 | NAS、电脑、灯光、空调 |
| 定时任务 | 让专家按计划主动执行工作 | 每晚整理家庭事项 |

连接器与通道不是同一概念：连接器让专家“使用外部数据与服务”，通道让用户“从另一个聊天平台发消息给专家”。

## 2. 安装与启动

### 2.1 环境要求

- Windows、macOS 或 Linux。
- 使用安装脚本时无需预先安装 Python；脚本会通过 `uv` 创建隔离环境。
- 默认使用 SQLite，不要求 Redis、消息队列或其他外部服务。
- 使用云端模型需要对应服务的网络和 API Key；使用 Ollama 可在本地运行模型。

### 2.2 一键安装

macOS / Linux：

```bash
curl -fsSL https://finnie-1258344699.cos.ap-guangzhou.myqcloud.com/octop/install.sh | bash
```

Windows PowerShell：

```powershell
irm https://finnie-1258344699.cos.ap-guangzhou.myqcloud.com/octop/install.ps1 | iex
```

也可以从 GitHub Releases 下载桌面客户端。桌面客户端适合单机使用；服务器或 NAS 部署更适合全家长期访问。

### 2.3 从源码运行

```bash
git clone https://github.com/fengjutian/HomeMind.git
cd HomeMind
uv sync
uv run homemind run
```

开发模式可启用自动重载：

```bash
uv run homemind run --reload
```

### 2.4 启动服务

```bash
homemind run
```

默认打开：<http://127.0.0.1:8088>。

允许局域网其他设备访问：

```bash
homemind run --host 0.0.0.0 --port 8088
```

> 不要直接把未配置 TLS 和访问控制的服务暴露到公网。公网使用应配置 HTTPS、防火墙和强密码。

HomeMind CLI 兼容 Octop 的管理命令，因此 `homemind agent`、`homemind provider`、`homemind backup` 等命令与对应的 `octop` 命令具有相同能力。

## 3. 首次初始化

首次访问会进入设置向导：

1. 验证一次性设置密码（启用设置保护时）。
2. 选择 SQLite 或 PostgreSQL。
3. 创建首个管理员账号。
4. 配置一个模型供应商，也可以暂时跳过。
5. 完成初始化并进入控制台。

管理员密码至少 8 位，并同时包含字母和数字。

无人值守环境可以先设置管理员变量，再执行初始化：

```bash
export OCTOP_ADMIN_USERNAME=admin
export OCTOP_ADMIN_PASSWORD='replace-with-a-strong-password'
homemind init --yes
homemind run
```

Windows PowerShell 使用 `$env:OCTOP_ADMIN_USERNAME` 和 `$env:OCTOP_ADMIN_PASSWORD` 设置变量。

## 4. 建议的首次使用顺序

完成向导后，建议按以下顺序配置：

1. **设置 → 模型**：确认模型测试成功。
2. **家庭**：创建家庭，设置名称与默认家庭。
3. **家庭成员**：邀请或绑定账号，确认成员角色。
4. **专家**：从内置模板创建第一个专家。
5. **对话**：用一个简单任务验证模型和专家。
6. **知识库或连接器**：只接入一个最常用的数据源。
7. **智能家居**：需要时再连接 Home Assistant。
8. **定时任务**：在人工对话稳定后再开启主动自动化。
9. **备份**：首次完成配置后立即创建一份备份。

不建议一开始就开启全部连接器、设备写权限和定时任务。先完成一条可验证的小闭环，再逐步增加能力。

## 5. 家庭空间与成员

### 5.1 创建家庭

进入 **家庭** 页面创建家庭。一个账号可以属于多个家庭，并可选择当前活动家庭。家庭功能中的文件、照片、记忆、日历和任务都会以活动家庭为作用域。

### 5.2 成员与角色

家庭成员可以绑定平台用户。建议至少区分：

- **所有者/管理员**：管理成员、权限、设备接入与高风险操作。
- **普通成员**：使用被授权的家庭空间、专家与设备。
- **儿童或受限成员**：仅开放必要空间与低风险能力。

成员之间不会因为属于同一家庭就自动共享全部私人对话。需要共享的内容应放入家庭空间、家庭知识库或明确开放的资源。

### 5.3 空间与权限

使用家庭空间组织不同范围的数据，例如“全家共享”“父母”“孩子学习”“家庭财务”。为成员或角色分配空间权限，避免用一个全能账号供所有人共用。

## 6. 专家、团队与对话

### 6.1 从模板创建专家

进入 **专家 → 内置专家**：

1. 选择模板。
2. 点击“从此模板新建”。
3. 设置名称、模型、工作区和其他高级参数。
4. 创建并启动专家。
5. 回到对话页选择该专家。

模板只是起点。创建后可以调整人设文件、技能、子智能体、连接器和知识库，不会修改原始模板。

### 6.2 自定义专家

创建专家时重点配置：

- **名称与说明**：让家人知道它负责什么。
- **模型**：按效果、隐私、成本选择。
- **系统提示与人格**：定义职责、边界和交付格式。
- **技能**：提供特定工作流程与工具说明。
- **知识库**：限定可信资料范围。
- **连接器**：只开放完成职责所需的外部服务。

遵循最小权限原则。例如，学习助手通常不需要邮箱发送权限，PPT 专家可能只需要文档、网盘和图片素材连接器。

### 6.3 专家团队

复杂任务可创建专家团队，由协调者把工作分给成员专家。适合：

- 研究 → 分析 → 写作 → 演示；
- 需求 → 架构 → 开发 → 测试；
- 家庭旅行中的行程、预算、天气和资料整理。

团队不会自动提升权限。每个成员专家仍受自己的工具和资源授权约束。详细机制见 [专家团队](expert-teams.md)。

### 6.4 对话与附件

在 **对话** 页面选择专家后即可发送消息。可以上传文件，查看工具调用过程，并在同一线程继续追问。上传到对话的附件会进入该专家工作区的 `inbound/` 目录。

高质量请求通常包含：目标、受众、输入资料、约束、输出格式和截止时间。

## 7. 模型接入

### 7.1 云端模型

进入 **管理 → 模型**，选择预设供应商或创建自定义供应商：

1. 选择 OpenAI、Anthropic、DeepSeek、通义、智谱等预设，或 OpenAI 兼容服务。
2. 填写 API Key 和 Base URL。
3. 选择或添加模型 ID。
4. 执行连接测试。
5. 保存，并为专家指定模型。

API Key 属于敏感数据，不要写入专家提示词、普通 Markdown 文件或公开仓库。

### 7.2 本地 Ollama

先安装并启动 Ollama，再在模型设置中选择 Ollama。默认情况下它使用本机服务地址，不需要 API Key。若 HomeMind 运行在容器中，`localhost` 指向容器自身，应改为宿主机可访问地址。

### 7.3 模型选择建议

- 日常问答：优先选择速度快、成本适中的模型。
- 复杂推理和多工具任务：选择工具调用稳定、上下文足够的模型。
- 私密资料：使用本地模型，或确认云服务的数据处理政策。
- 不同专家可选择不同模型，无需全局统一。

## 8. 连接器接入

连接器让专家读取或操作外部服务。目前内置目录覆盖文档、会议、邮箱、网盘、知识库、任务、旅行、地图、法律和企业信息等场景。

### 8.1 连接内置服务

进入 **连接器 → 内置连接器**：

1. 选择目标服务并点击“连接”。
2. 按页面提示执行 OAuth 登录，或填写 API Key、Token、应用凭证。
3. 保存后执行连接测试或刷新状态。
4. 在专家设置中选择允许使用的连接器。
5. 用只读问题验证，例如“列出我最近的五份文档”。
6. 确认无误后再尝试创建、修改或发送操作。

### 8.2 自定义 MCP 连接器

如果服务已经提供 MCP Server，可进入 **连接器 → 自定义连接器** 添加。通常需要：

- 唯一名称和显示名称；
- MCP Server URL 或本地启动命令；
- `streamable_http`、SSE 或 stdio 等传输方式；
- Header、Token 或 OAuth 信息；
- 是否默认向新对话开放。

接入前应核对 MCP Server 暴露的工具列表。不要把删除、付款、公开发布等高风险工具默认开放给所有专家。

### 8.3 连接器排查

- **显示已连接但专家不会用**：检查该专家是否启用了连接器，重启或重载专家。
- **OAuth 回调失败**：检查服务是否通过 HTTPS 或 localhost 访问，以及回调地址是否与服务商登记一致。
- **Token 测试失败**：检查 Token 是否完整、是否过期、Scope 是否足够。
- **工具太多导致选择不稳定**：缩小允许工具列表，只保留当前业务所需能力。

## 9. 知识库与家庭文件

### 9.1 知识库

进入 **知识库** 创建知识库并上传资料。知识库适合稳定、需要引用或检索的内容，例如课程资料、家庭规则、产品手册和项目文档。

上传后等待索引完成，再将知识库绑定到专家。建议用资料中可以明确回答的问题验证检索效果，并要求专家说明依据。

### 9.2 家庭文件与照片

家庭文件和照片属于家庭作用域，可按空间及权限共享。大量文件扫描、缩略图或索引可能以后台任务执行，可在相应页面查看进度。

不要把“专家工作区”“家庭文件”和“知识库”混为一处：

- 专家工作区保存专家自己的文件和产物；
- 家庭文件用于成员共享与管理；
- 知识库用于检索增强问答。

## 10. 智能家居接入

HomeMind 当前不直接保存小米、华为等厂商账号密码。受支持的主要路径是：

```text
厂商设备 → Home Assistant → HomeMind → 家庭审批 → 执行
```

接入步骤：

1. 先在 Home Assistant 中完成厂商设备接入。
2. 确认设备在 Home Assistant 内可以正常查看或控制。
3. 创建 Home Assistant 长期访问令牌。
4. 在 HomeMind 的 **智能家居** 页面新增 Home Assistant 接入方。
5. 填写地址和令牌并同步实体。
6. 检查设备、房间和能力映射。
7. 先测试读取状态，再测试低风险写操作。

门锁、摄像头和安防面板等高风险领域默认只读；空调、窗帘、风扇等操作需要审批。完整规则见 [智能家居接入指南](smart-home-setup.md)。

## 11. 消息渠道接入

进入 **个性化 → 通道**，为专家配置飞书、钉钉、QQ、企业微信、Discord 等消息入口。

一般流程：

1. 在消息平台创建机器人或应用。
2. 获取 App ID、Secret、Token 等凭据。
3. 在 HomeMind 选择目标专家并创建通道。
4. 填写凭据，按平台要求配置回调或长连接。
5. 执行通道测试。
6. 从平台发送一条简单消息确认身份和路由。

一个通道通常绑定一个专家。需要不同职责时，优先为不同专家创建独立入口，而不是让一个机器人拥有全部能力。

## 12. 任务、日历与自动化

### 12.1 家庭任务与日历

家庭任务、任务看板、日历和提醒用于家庭成员之间的结构化协作。时间显示和调度统一使用服务器的 `default_timezone`，不是浏览器本地时区。

### 12.2 专家定时任务

进入 **定时任务**，选择专家、执行计划和提示词。首次创建时建议：

- 使用低风险、只读任务；
- 先手动“立即运行”验证；
- 明确时区与发送目标；
- 输出先保存草稿，不自动外发；
- 运行稳定后再开启通知或写操作。

示例：

> 每周五 17:00 汇总本周家庭任务，列出已完成、延期和下周重点，发送给我确认。

## 13. 外部项目接入 HomeMind

### 13.1 HTTP API

HomeMind 在 Octop FastAPI 应用上挂载家庭 API，路径以 `/api/homemind/` 开头；通用专家、对话、连接器等 API 位于 `/api/`。

开发环境可在 `config.json` 设置：

```json
{
  "enable_api_docs": true
}
```

重启后访问：

- Scalar 文档：`/api/docs`
- OpenAPI：`/api/openapi.json`

外部调用应使用正式登录获得的 JWT，不要绕过用户身份。家庭 API 会根据当前用户校验家庭成员关系和权限。

### 13.2 HomeMind MCP Server

外部 MCP 客户端可通过以下入口使用家庭工具：

```text
POST /api/homemind/mcp
Authorization: Bearer <dashboard-jwt>
Content-Type: application/json
```

该端点支持 `initialize`、`tools/list`、`tools/call` 和 `ping`。调用者身份来自 JWT，而不是工具参数；服务端会解析当前活动家庭、执行权限判断，并把需要确认的操作送入家庭事务与审批流程。

请求示例：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}
```

MCP 客户端还可以提供 `X-MCP-Client` 和 `X-MCP-Session` 作为审计标签，但这些 Header 不参与授权。

### 13.3 插件、技能和连接器怎么选

| 目标 | 扩展方式 |
|------|----------|
| 教专家遵循一种工作流程 | 技能包 |
| 给多个专家增加平台级功能 | 插件 |
| 访问一个外部应用或账号 | 连接器 / MCP |
| 让外部程序调用 HomeMind 家庭工具 | HomeMind MCP Server |
| 构建独立前端或自动化系统 | HTTP API |
| 连接另一个 Octop/HomeMind 实例 | Bridge |

## 14. 权限、安全与审批

建议遵循以下原则：

- 每位家庭成员使用独立账号，不共享管理员密码。
- 普通专家只获得完成职责所需的连接器和工具。
- 外部写操作默认先确认；删除、付款、公开发布等操作必须人工审批。
- 门锁、摄像头、安防等能力保持只读，除非经过专门安全评审。
- 公网部署启用 TLS，并限制 CORS、反向代理与防火墙规则。
- 定期检查审计日志、连接器授权和不再使用的 Token。
- 离开家庭或停用账号时，及时撤销成员关系、设备令牌和连接器授权。

工具审批和 Shell 护栏位于 **管理 → 安全**。家庭设备操作还会经过家庭事务和审批机制，两层规则互不替代。

## 15. 数据、备份与迁移

默认运行数据位于 `~/.octop/`，可用 `OCTOP_HOME` 覆盖。主要内容包括：

```text
~/.octop/
├── config.json
├── octop.db
├── secrets/
├── agents/
├── plugins/
├── logs/
└── homemind/
    └── exports/
```

### 15.1 创建备份

```bash
homemind backup --help
```

备份后应在另一位置保存副本，并验证归档可以读取。SQLite 与 PostgreSQL 的备份不能跨数据库引擎直接恢复。

### 15.2 家庭导出

家庭层还提供家庭数据导出与分阶段导入。导入先进入暂存状态，确认内容和目标家庭后再应用，避免直接覆盖现有家庭数据。

### 15.3 升级前检查

1. 创建系统备份和必要的家庭导出。
2. 记录当前版本和数据库类型。
3. 阅读目标版本发布说明。
4. 升级后检查登录、模型、专家、连接器、通道和定时任务。
5. 再恢复自动外发或设备写操作。

## 16. 运维与故障排查

### 16.1 页面打不开

- 确认 `homemind run` 仍在运行。
- 检查访问端口与启动参数一致。
- 局域网访问时确认使用 `--host 0.0.0.0`，并放行防火墙端口。
- 查看 `~/.octop/logs/` 下的日志。

### 16.2 专家没有回复

- 确认模型供应商连接测试成功且有余额。
- 确认专家状态为运行中。
- 检查专家是否绑定了有效模型。
- 查看工具审批是否正在等待人工确认。

### 16.3 新增内置专家未显示

内置专家目录在服务启动时扫描。源码中新增模板后，需要重启 HomeMind；已经打包的桌面应用还需要重新构建或安装新版本。

### 16.4 连接器不能调用

- 确认连接器实例状态正常。
- 确认当前专家已启用该连接器。
- 检查 Token、OAuth Scope 和服务端网络。
- 修改连接器配置后重载专家。

### 16.5 智能设备不同步

- 先确认设备在 Home Assistant 中正常。
- 检查 Home Assistant 地址能否从 HomeMind 所在主机访问。
- 检查长期令牌权限与有效期。
- 重新同步实体；连接断开时系统不会盲目删除已有设备。

### 16.6 时间不正确

在 `~/.octop/config.json` 设置 IANA 时区：

```json
{
  "default_timezone": "Asia/Shanghai"
}
```

或设置 `OCTOP_DEFAULT_TIMEZONE`，然后重启服务。

## 17. 推荐配置方案

### 17.1 个人试用

- SQLite；
- 一个云端模型或本地 Ollama；
- 一个通用专家；
- 暂不启用外部写权限；
- 仅通过 Web 或桌面端使用。

### 17.2 家庭长期使用

- 运行在常开电脑或 NAS；
- 每位成员独立账号；
- 按家庭空间分配权限；
- Home Assistant 统一接入设备；
- 对设备写操作开启审批；
- 定期备份 `OCTOP_HOME`。

### 17.3 开发与集成

- 源码安装并使用 `homemind run --reload`；
- 开启 API 文档；
- 使用独立测试家庭和低权限账号；
- 通过 HTTP API 或 HomeMind MCP Server 集成；
- 对写操作测试权限拒绝、审批、重试和审计记录；
- 提交前运行项目规定的 `make all`。
