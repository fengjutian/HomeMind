# HomeMind 独立大模型部署需求

**状态：** Draft  
**适用范围：** HomeMind / Octop 模型供应商、Agent 推理、知识库 Embedding、Dashboard 运维界面  
**目标版本：** 待排期  
**推荐首发运行时：** Ollama  
**兼容协议：** OpenAI-compatible API  

---

## 1. 背景

HomeMind 需要支持在家庭局域网或完全离线环境中使用独立部署的大模型。模型服务可能运行在与 HomeMind 相同的主机，也可能运行在独立 GPU 工作站、NAS 或家庭计算节点上。

当前系统已经具备模型 Provider、Ollama 管理、OpenAI-compatible 接入和独立 Embedding 配置等基础能力。本需求不在 HomeMind Web 进程中重新实现推理引擎，而是在现有 Provider 体系上补齐独立模型服务的配置、探测、能力识别、故障呈现和隐私约束。

## 2. 产品目标

1. 用户可以把 HomeMind 连接到独立运行的本地模型服务，无需使用公有云模型。
2. HomeMind 与模型运行时解耦，模型下载、显存管理、升级和重启不影响 HomeMind 核心进程的生命周期。
3. 对话、工具调用、视觉和 Embedding 等能力可分别配置，不假设单一模型具备全部能力。
4. 用户可以明确启用“仅本地模型”策略，保证模型不可用时不会静默把数据发送到云端。
5. Dashboard 能准确呈现模型服务的可用、加载中、过载和离线状态，并提供可诊断的错误信息。
6. 首版以单个独立推理端点可靠可用为目标，为以后接入家庭计算节点和多模型调度保留协议边界。

## 3. 非目标

本期不包含：

- 在 HomeMind FastAPI 进程内加载或运行模型权重；
- 自研模型推理引擎、模型格式或模型仓库；
- 多机训练、微调或分布式推理；
- 自动跨节点迁移正在执行的推理请求；
- 通用 GPU 集群管理、复杂抢占式调度或家庭版 Kubernetes；
- 将任意远程 Shell 作为模型节点管理能力；
- 在无用户明确授权时自动回退到云模型；
- 首版同时深度适配 Ollama、vLLM、llama.cpp、MLX 等所有运行时的私有管理接口。

## 4. 产品原则

### 4.1 推理服务独立

HomeMind 只负责保存端点、模型标识、凭据引用、能力与策略。模型权重、GPU 驱动、推理缓存和运行时进程由独立模型服务管理，不进入 HomeMind Python 进程。

### 4.2 标准协议优先

通用推理请求优先使用 OpenAI-compatible API。Ollama 可提供额外的本地模型发现、下载和服务管理体验，但 Agent 领域逻辑不得依赖 Ollama 私有协议。

### 4.3 能力显式声明并经探测验证

模型需要区分以下能力：

- `chat`：普通对话；
- `tools`：结构化工具调用；
- `vision`：图片输入；
- `embedding`：向量生成；
- `streaming`：流式输出。

用户声明的能力用于配置，连接测试得到的结果用于提示和诊断。不得仅因模型名称推断其一定支持工具或视觉能力。

### 4.4 本地优先，失败透明

模型离线、超时、过载或不支持所需能力时，系统必须返回明确状态。除非用户显式配置回退链，HomeMind 不得静默改用其他 Provider；“仅本地模型”策略下禁止任何云端回退。

### 4.5 凭据和正文最小暴露

API Key 只保存在现有 secrets/provider 体系，不进入普通配置、日志、审计正文或 API 响应。健康探测和指标默认不得记录完整提示词、附件正文或模型原始响应。

## 5. 典型部署形态

### 5.1 同机部署

HomeMind 与 Ollama 运行在同一台主机，通过回环地址通信。适用于单用户试用和低成本部署。

### 5.2 局域网分离部署（推荐）

```text
家庭成员 / Agent
       │
       ▼
HomeMind 常驻主机
       │  OpenAI-compatible API（家庭局域网）
       ▼
独立 GPU 推理主机
  ├── 对话 / 工具模型
  ├── 可选视觉模型
  └── Embedding 模型
```

HomeMind 可运行在低功耗主机或 NAS，GPU 主机可以独立重启或休眠。模型主机离线不得导致 HomeMind 的认证、设备管理、日历等非模型功能不可用。

### 5.3 完全离线部署

模型推理、Embedding 和相关文件处理均在家庭网络完成。安装和升级所需的模型文件由用户预先导入；运行时不得依赖公网服务。

## 6. 术语

| 术语 | 定义 |
|---|---|
| 模型 Provider | HomeMind 中保存协议类型、端点、凭据引用及模型目录的配置实体。 |
| 推理端点 | 提供模型 API 的独立服务地址。 |
| 模型能力 | `chat`、`tools`、`vision`、`embedding`、`streaming` 等可验证特征。 |
| 仅本地策略 | 禁止请求和数据自动回退到被标记为云端的 Provider。 |
| 连接测试 | 对端点连通性、认证、模型存在性和关键能力进行的受限探测。 |
| 模型预热 | 触发模型加载但不承载正式用户请求的操作。 |

## 7. 功能需求

### 7.1 Provider 配置

系统应复用现有 Provider 体系，至少支持配置：

| 字段 | 要求 |
|---|---|
| 名称 | 用户可识别，同一作用域内按现有规则唯一。 |
| Provider 类型 | 首版支持 Ollama 和自定义 OpenAI-compatible。 |
| `base_url` | 必填；保存前规范化，展示时不得拼入凭据。 |
| API Key | 可选；通过现有秘密存储持久化，读取接口只返回是否已配置。 |
| 模型列表 | 支持从端点发现，也支持用户手工增加模型标识。 |
| 默认用途 | 可分别选择对话、工具、视觉和 Embedding 模型。 |
| 本地属性 | 明确标记该 Provider 是否属于本地可信边界，不根据 URL 自动作最终判断。 |
| 超时 | 使用安全默认值；首版不提供过多细粒度旋钮。 |
| 启用状态 | 禁用后不可承接新请求，但保留配置。 |

编辑 Provider 时，不得因为连接测试失败而丢失用户已保存的合法配置。删除正在被 Agent 或知识库引用的 Provider 时，应阻止删除并列出引用，或要求用户先迁移依赖。

### 7.2 连接与能力测试

用户保存配置前后均可发起连接测试。测试至少分阶段返回：

1. URL 可访问；
2. 身份认证有效；
3. 能获取模型列表，或手工指定的模型存在；
4. 模型可以完成最小对话请求；
5. 若声明 `streaming`，可收到有效流式片段；
6. 若声明 `tools`，可返回结构化工具调用；
7. 若声明 `embedding`，可返回稳定维度的数值向量；
8. 若声明 `vision`，可接受最小测试图片。

测试结果需包含阶段、状态、耗时、可读错误码和最近测试时间，不返回凭据和完整测试提示词。未测试不等于不支持；探测失败也不得伪装成“模型不存在”。

### 7.3 模型目录与选择

- Ollama 可复用现有模型列举、下载和删除能力。
- 自定义 OpenAI-compatible 端点优先读取模型列表；端点不支持模型列举时允许手工添加模型标识。
- 模型选择界面显示 Provider、模型标识、已验证能力、最近状态和本地/云端标签。
- Agent 保存时校验模型至少具备 `chat`；启用工具的 Agent 应提示模型的 `tools` 能力状态。
- Embedding 配置必须与对话模型分离，并记录向量维度。切换 Embedding 模型或维度时，不得继续混用旧索引，应要求或触发明确的重建流程。

### 7.4 请求执行

- HomeMind 使用 Provider 与模型配置组装请求，不直接操作模型权重或 GPU。
- 支持普通与流式对话；客户端取消后应尽力取消上游请求并停止继续消费响应。
- 对模型端点设置连接超时、首 token 超时和总请求上限；具体默认值在实施阶段根据现有 Provider 行为确定。
- 上游错误需映射为稳定的领域错误，例如：`provider_unavailable`、`authentication_failed`、`model_not_found`、`capability_unsupported`、`request_timeout`、`provider_overloaded`。
- 不得把上游返回的未过滤错误正文直接展示给普通用户，以免泄漏服务路径、提示词或凭据片段。

### 7.5 本地策略与回退

系统至少支持两种策略：

- `STRICT_LOCAL`：当前请求只允许使用被明确标记为本地的 Provider，失败后直接返回错误；
- `EXPLICIT_CHAIN`：用户明确配置有序回退链，系统仅按该链尝试。

要求：

- 默认不得创建隐式云端回退；
- 每个回退目标在配置时显示本地/云端属性；
- 涉及附件、家庭知识库或设备上下文时，若下一目标越出本地边界，应再次遵循现有隐私与授权策略；
- 审计记录 Provider 和模型标识、是否发生回退及错误类别，但不默认保存完整提示词；
- `STRICT_LOCAL` 在所有调用入口保持一致，包括聊天、后台 Agent、定时任务和知识库 Embedding。

### 7.6 状态与运维

Provider 状态至少包括：

- `UNKNOWN`：尚未探测；
- `AVAILABLE`：可接受请求；
- `LOADING`：服务在线但模型正在加载；
- `DEGRADED`：部分能力失败或延迟显著升高；
- `OVERLOADED`：服务拒绝或无法及时处理新请求；
- `OFFLINE`：端点不可达；
- `AUTH_ERROR`：认证失败；
- `MISCONFIGURED`：模型不存在或配置不合法。

Dashboard 应显示最近成功时间、最近测试时间、最近错误类别和建议动作。状态必须有新鲜度，过期探测不得长期显示为“可用”。首版以按需探测和低频后台探测为主，不建设高频监控系统。

### 7.7 Ollama 特有体验

在不影响通用 Provider 边界的前提下，保留或补齐：

- 检测本机 Ollama 服务；
- 在用户明确操作时启动本机 Ollama；
- 展示本地已安装模型；
- 下载进度、成功、失败和取消状态；
- 删除未被 Agent、默认模型或 Embedding 配置引用的模型；
- 支持现有自定义模型目录设置。

对于远程 Ollama，HomeMind 不应默认尝试管理其操作系统进程或模型目录，只通过服务 API 完成允许的操作。

### 7.8 模型预热

- 用户可手动预热已配置模型。
- 请求结果应区分“预热成功”“端点在线但仍在加载”和“预热失败”。
- 首版不承诺 HomeMind 启动时自动预热所有模型，以避免家庭设备同时占用大量内存或显存。
- 后续如增加定时预热或 Wake-on-LAN，必须作为独立需求评审其权限、功耗和失败恢复。

## 8. 安全需求

### 8.1 网络边界

- 推荐仅在可信局域网、VPN 或受控容器网络中暴露推理端点，不直接暴露公网。
- 对远程地址执行现有适用的 URL 规范化和 SSRF 防护；同时需要允许管理员显式配置家庭局域网端点，不能套用“只允许公共 HTTPS”的云服务规则。
- “允许私网地址”必须受管理员权限控制，不得由普通用户绕过网络策略。
- 跨非可信网络部署时应使用 HTTPS；后续可扩展 mTLS，但不作为首版强制要求。

### 8.2 身份与凭据

- 支持无凭据的受信局域网 Ollama，以及带 API Key 的 OpenAI-compatible 服务。
- API Key 写入、轮换和删除遵循现有 Provider secret 机制。
- 列表、详情、导出、日志与异常中不得出现明文 API Key。
- 连接测试不得把凭据写入任务参数、审计正文或前端状态缓存。

### 8.3 数据保护

- 默认不记录完整提示词、附件内容、知识库片段和模型原始响应。
- 诊断日志只记录请求 ID、Provider、模型、耗时、token 统计和错误类别。
- 若用户启用详细调试日志，界面必须说明潜在敏感数据风险，并设置明确的关闭方式与保留期限。
- 云端回退不能绕过家庭数据访问控制和 Agent 权限。

## 9. 非功能需求

### 9.1 可用性

- 模型 Provider 故障不得阻塞 HomeMind 启动。
- 单个 Provider 故障不得影响其他 Provider 和非模型家庭功能。
- HomeMind 重启后应恢复 Provider 配置和策略，但不恢复已中断的流式响应。
- 取消或超时后不得无限占用 HomeMind 内部任务槽位。

### 9.2 性能与并发

- 首版允许为本地 Provider 设置保守的并发上限；超出上限时应排队或返回明确的过载状态。
- 队列必须有长度和等待时限，禁止无界积压。
- 状态探测不能与用户请求争抢大量推理资源；能力深度测试仅由用户主动触发或在低频维护任务中执行。
- 系统记录首 token 延迟、总耗时、成功/失败数和过载次数，不记录请求正文。

### 9.3 兼容性

- 支持 SQLite 和 PostgreSQL；若新增 schema，按仓库规则提供成对迁移。
- 后端异步路径不得直接执行阻塞网络或文件 I/O。
- Dashboard 时间使用服务端 `default_timezone`。
- 用户可见文案进入中英文 i18n，不硬编码在领域层。
- 变更不得破坏现有云 Provider、Agent 模型选择和 Ollama 模型管理行为。

## 10. 建议架构与模块边界

优先扩展现有模型 Provider、Agent settings 和 Ollama 管理能力，不因本需求创建一套平行的“HomeMind 模型配置”。

建议职责：

- `infra/agents/providers/`：Provider 协议适配、能力测试、错误归一化；
- `infra/agents/settings/`：Agent 模型选择和本地策略；
- `infra/utils/ollama_manager.py`：仅保留 Ollama 进程与模型资产相关的底层能力；
- `infra/db/repos/`：Provider、能力探测结果和引用关系所需 SQL；
- `api/routers/`：配置校验、权限检查、调用领域服务、映射 HTTP 响应；
- `dashboard/src/api/`：类型化 Provider 与探测 API；
- `dashboard/src/pages/`：配置、连接测试、状态和模型选择体验。

API 路由不得直接调用推理 SDK、访问数据库 Repo 或实现回退策略。Agent 运行时不得直接启动 Ollama 进程；本机服务管理只能由明确的管理操作触发。

## 11. API 契约要求

实施时优先扩展现有 Provider API，而非新增语义重复的 `/local-models` 资源。至少需要覆盖以下操作语义：

- 创建、更新、查询和删除独立模型 Provider；
- 发起连接/能力测试并返回分阶段结果；
- 查询模型目录；
- 查询 Provider 当前状态；
- 手动预热指定模型；
- 配置 Agent 的模型及本地/回退策略；
- 查询 Provider 被 Agent、默认配置和知识库引用的情况。

所有新增或调整的路由必须提供清晰的 OpenAPI `summary`、请求/响应模型、字段说明和稳定错误码，并在 `/api/docs` 中可读。

## 12. Dashboard 需求

### 12.1 Provider 配置页

- 区分“本机 Ollama”“局域网模型服务”“自定义 OpenAI-compatible 服务”；
- 表单展示端点、凭据状态、本地属性、模型和用途；
- 保存与连接测试是两个明确动作；
- 测试结果按阶段展示，不只显示单一成功/失败 Toast；
- 敏感字段编辑后不可反显原值。

### 12.2 模型状态

- 展示状态、最近成功时间、响应耗时和最近错误；
- `LOADING` 与 `OFFLINE` 使用不同文案和建议；
- 用户可重新测试或手动预热；
- 状态过期时显示“状态未知/待重新检查”，不继续显示绿色可用。

### 12.3 Agent 模型设置

- 模型列表展示 Provider、本地/云端标记和已验证能力；
- 启用工具或视觉但模型能力未验证时给出警告；
- `STRICT_LOCAL` 以清晰文案说明“失败时不会使用云模型”；
- 配置显式回退链时展示数据可能离开本地网络的边界变化。

## 13. 分阶段交付

### 阶段 0：现状审计与契约冻结

1. 盘点现有 Provider、Ollama、Agent 模型和 Embedding 数据流。
2. 为已有云 Provider、Ollama 模型管理和 Agent 模型解析补充契约测试。
3. 明确当前 Provider 表结构、秘密存储方式和错误码，避免平行实现。

**完成标准：** 形成现状矩阵，关键既有行为有测试保护，未修改产品行为。

### 阶段 1：单端点 MVP

1. 支持保存一个独立 Ollama 或 OpenAI-compatible 端点。
2. 支持模型发现或手工模型标识。
3. 实现分阶段连接测试：连通、认证、模型存在、最小对话与流式输出。
4. Agent 可选择该模型并完成流式对话。
5. 支持 `STRICT_LOCAL`，模型失败时不回退云端。
6. Dashboard 显示 `AVAILABLE`、`OFFLINE`、`AUTH_ERROR`、`MISCONFIGURED`。

**完成标准：** 没有公网入口的局域网 GPU 主机可为 HomeMind Agent 提供模型服务；断开模型主机后，用户收到明确错误，且请求未发送到云端。

### 阶段 2：能力与知识库

1. 增加工具调用、视觉和 Embedding 能力测试。
2. 对话与 Embedding 分别选择模型。
3. Embedding 维度变化触发明确的索引重建流程。
4. 增加模型预热、过载状态、有限并发和有界队列。
5. 补齐状态指标与运维界面。

**完成标准：** 工具 Agent 和知识库可各自使用经过验证的本地模型；能力不匹配、过载和模型加载状态均可诊断。

### 阶段 3：家庭计算节点集成（后续）

1. 将模型端点与家庭计算节点的在线状态、GPU 能力关联。
2. 支持受控的 Wake-on-LAN 和定时预热。
3. 支持用户显式配置多个本地端点和回退顺序。
4. 根据能力、状态和并发进行有限调度。

该阶段需要独立的节点身份、授权和任务协议设计，不应阻塞阶段 1、2。

## 14. MVP 验收标准

### 14.1 基本流程

- 管理员可配置局域网内独立 Ollama 或 OpenAI-compatible 端点。
- API Key 不会通过读取接口、日志或错误消息返回。
- 连接测试能区分端点不可达、认证失败和模型不存在。
- Agent 可选择已配置模型完成普通及流式对话。
- 重启 HomeMind 后配置仍有效，无需重建模型数据。

### 14.2 隐私与失败

- 启用 `STRICT_LOCAL` 后，断开本地模型服务不会产生任何云 Provider 请求。
- 模型超时或过载时，用户收到稳定、可本地化的错误信息。
- Provider 故障不影响登录、家庭设备查看等非模型功能。
- 日志和审计默认不包含完整提示词、附件正文或 API Key。

### 14.3 兼容性

- 现有云 Provider 配置及 Agent 继续工作。
- 现有 Ollama 模型列举、下载和删除功能不退化。
- SQLite、PostgreSQL 的新增持久化行为一致。
- Windows 和 Linux 测试不依赖固定路径、POSIX 权限或 Unix 命令。

## 15. 测试要求

### 15.1 单元测试

- URL 规范化和私网策略；
- 凭据脱敏；
- 能力探测结果归一化；
- 上游错误到领域错误的映射；
- `STRICT_LOCAL` 和显式回退链选择；
- 并发限制、队列上限、取消与超时；
- Embedding 维度变更保护；
- Provider 引用检查。

### 15.2 集成测试

使用可控 fake server 模拟 OpenAI-compatible 端点，覆盖：

- 正常对话和流式响应；
- 401/403、404 模型不存在、429/503 过载；
- 首 token 超时、中途断流和畸形响应；
- 模型列表接口不存在但手工模型可用；
- 工具调用、视觉和 Embedding 能力支持/不支持；
- 本地 Provider 失败时禁止云端回退；
- HomeMind 重启后的配置恢复。

CI 不依赖真实 GPU、Ollama 安装、家庭网络或公网模型服务。Ollama 实机验证作为可选手工测试或显式 `live` 测试。

## 16. 开放问题

以下问题需要在实施对应阶段前确认：

1. `STRICT_LOCAL` 是 Agent 级、家庭级，还是同时支持两级且由更严格策略优先？
2. 局域网私有地址的允许名单由全局管理员配置，还是绑定到具体 Provider？
3. 首版是否允许 HomeMind 管理远程 Ollama 的模型下载/删除，还是只允许读取与推理？
4. Provider 健康状态是否需要持久化历史，或仅保存最近一次结果并通过指标系统统计？
5. 本地推理的默认并发上限如何按设备能力设定；首版是否固定为每 Provider 单并发？
6. 详细诊断模式允许记录哪些提示信息，其开启权限和自动关闭时间如何定义？
7. 完全离线安装所需的模型导入、校验和许可证提示是否纳入独立交付包？

## 17. 决策建议

若上述开放问题尚未决策，建议 MVP 采用以下默认值：

- `STRICT_LOCAL` 先作为 Agent 级策略，后台任务继承所属 Agent 的策略；
- 私网端点只允许管理员创建和编辑；
- 远程 Ollama 首版只读取模型并执行推理，不管理远程进程和模型资产；
- 只保存最近一次健康结果，历史趋势进入指标而非业务表；
- 每个本地 Provider 默认单并发、有界短队列；
- 详细诊断默认关闭，且永不记录 API Key；
- 完全离线模型导入作为独立部署指南，不阻塞单端点 MVP。
