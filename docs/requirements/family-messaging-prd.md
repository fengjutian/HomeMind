# HomeMind 家庭消息产品需求

状态：草案  
目标读者：产品、设计、前端、后端、测试与安全负责人  
适用范围：HomeMind Web 与后续原生客户端  

## 1. 产品结论

HomeMind 应提供一个以家庭为边界的实时消息空间，让家庭成员像使用微信群一样发送文字和媒体消息，并可在需要时通过 `@家庭助手` 邀请 AI 参与。首版只提供每个家庭一个默认群聊，不提供成员私聊、多群、语音通话或视频通话。

家庭消息必须使用独立于现有 Agent `threads` 的数据模型和权限体系。普通家庭消息不得自动进入 Agent 上下文、长期记忆或外部模型；只有成员明确提及家庭助手或执行明确的“交给助手”操作后，相关消息才可进入一次 AI 处理流程。

## 2. 背景与问题

HomeMind 已具备家庭、成员、邀请、家庭通知、附件上传和 Agent 对话能力，但缺少家庭成员之间的通信入口。家庭事务仍需要借助微信等外部工具协调，导致日程、任务、照片、设备事件和家庭知识与讨论过程分离。

家庭消息的价值不是替代完整社交软件，而是把家庭协作放回 HomeMind 的家庭上下文中：成员可以围绕家庭日程、提醒、照片和设备事件进行讨论，并在明确授权后让家庭助手理解和执行请求。

## 3. 产品目标与非目标

### 3.1 产品目标

1. 家庭成员能够在一个默认家庭群中实时发送和接收消息。
2. 支持文字、图片、音频、视频和普通文件，复用现有上传与媒体预览能力。
3. 提供可靠的消息历史、离线补偿、未读计数和已读位置。
4. 通过 `@家庭助手` 提供可控的 AI 参与方式，同时保护普通家庭聊天隐私。
5. 与家庭成员权限、审计、通知和数据导出机制保持一致。
6. Web 首版完成后，协议可供后续移动端复用。

### 3.2 非目标

首版不包含：

- 家庭成员一对一私聊。
- 创建多个群、临时群或跨家庭群。
- 实时语音通话、视频通话、屏幕共享。
- 朋友圈、动态、红包、支付和小程序。
- 端到端加密。首版采用服务端加密存储与传输层加密；端到端加密需要单独设计密钥恢复、多设备同步和 AI 参与机制。
- 与微信个人账号消息互通或模拟微信协议。
- 自动把全部家庭聊天写入家庭记忆。

## 4. 用户与权限

### 4.1 用户角色

| 角色 | 权限 |
| --- | --- |
| 家庭管理员 | 进入家庭群、发送消息、管理成员、配置群设置、查看必要审计记录 |
| 普通家庭成员 | 进入家庭群、发送消息、查看历史、管理自己的消息和通知偏好 |
| 已邀请未加入用户 | 无权读取任何消息或附件 |
| 已退出或被移除成员 | 从成员关系失效时起无权读取群聊和附件；历史数据保留策略见第 15 节 |
| 家庭助手 | 仅在被明确提及或收到明确转交动作时读取授权上下文并回复 |

### 4.2 权限原则

- 每次读取、发送、编辑、撤回、上传和下载请求都必须校验当前用户属于目标 `family_id`。
- 不能只依赖客户端保存的当前家庭；服务端必须校验会话与家庭的真实关系。
- 会话列表只能返回当前用户有权访问的家庭会话。
- 附件访问权限继承消息权限，不能仅凭文件 URL 访问。
- 家庭管理员不能修改成员发送的消息正文，但可按治理规则隐藏违规消息；隐藏操作必须留审计记录。
- 成员被移除后，服务端应立即拒绝其现有 HTTP 和 WebSocket 会话继续访问该家庭频道。

## 5. 核心用户流程

### 5.1 首次进入家庭群

1. 用户加入或创建家庭。
2. 系统为家庭幂等创建一个默认会话，显示名称为“家庭群”。
3. 用户从侧边栏“家庭消息”进入会话。
4. 客户端加载最近一页消息并建立实时连接。
5. 用户可继续向上翻页加载历史消息。

### 5.2 发送文字消息

1. 用户输入文字并点击发送或按 Enter。
2. 客户端生成 `client_message_id`，立即显示“发送中”状态。
3. 服务端鉴权、去重并持久化消息。
4. 服务端返回正式 `message_id` 和服务端时间，同时向在线成员广播。
5. 发送失败时保留草稿并允许重试；相同 `client_message_id` 重试不得生成重复消息。

### 5.3 发送媒体或文件

1. 用户选择文件，客户端展示文件名、类型、大小和预览。
2. 小文件使用现有上传入口；超过前端阈值的文件使用上传会话进行断点续传。
3. 上传完成后，客户端发送引用附件资源的消息。
4. 消息持久化成功前，附件处于待关联状态；失败或取消产生的孤立附件由后台任务清理。
5. 接收端按媒体类型展示图片、视频、音频播放器或文件卡片。

### 5.4 离线恢复

1. 客户端重连时携带该会话最后确认的事件序号。
2. 服务端从持久化消息接口返回缺失数据，不依赖 WebSocket 缓冲区保存完整历史。
3. 客户端按消息游标合并数据并去重。
4. 若游标失效，客户端重新拉取最近消息并显示非阻塞提示。

### 5.5 邀请家庭助手

1. 用户输入 `@家庭助手`，或在某条消息上选择“交给家庭助手”。
2. 客户端清楚显示将要发送给 AI 的上下文范围。
3. 服务端创建一次助手调用，只传递触发消息、被引用消息及有限数量的必要上下文。
4. 助手回复作为 `sender_type=ASSISTANT` 的家庭消息写入同一会话。
5. 涉及设备控制、删除、支付或隐私数据等高风险动作时，继续使用现有预览、批准、执行和审计机制。

## 6. 功能需求

### 6.1 会话列表和入口

- 侧边栏增加“家庭消息”入口，并展示所有可访问家庭的默认群。
- 每个会话行显示家庭名称、最后一条消息摘要、时间、未读数和静音状态。
- 当前激活家庭的群聊优先显示，但切换家庭不能丢失其他家庭未读状态。
- 没有家庭时展示创建或加入家庭的引导。
- 成员关系失效后，会话应立即从列表移除。

### 6.2 消息时间线

- 消息按服务端序号稳定排序，同一毫秒内也不能乱序。
- 消息气泡显示发送者昵称、头像、正文、服务端时间和状态。
- 连续同一发送者的消息可合并头像展示，但不得隐藏日期边界。
- 时间显示使用服务端 `default_timezone`。
- 支持日期分隔、加载更早消息、回到底部和新消息提示。
- 当用户正在查看较早消息时，新消息到达不得强制滚动到底部。

### 6.3 消息类型

首版支持：

| 类型 | 行为 |
| --- | --- |
| 文本 | 支持换行、链接识别、emoji；不执行任意 HTML |
| 图片 | 缩略图、点击预览、原图下载 |
| 音频 | 原生播放控件、时长、加载失败降级为文件卡片 |
| 视频 | 内联播放、全屏、画中画由浏览器能力决定 |
| 文件 | 文件名、大小、类型、下载状态 |
| 系统消息 | 成员加入、退出、移除、群设置变化等不可回复事件 |
| 助手消息 | 明确标注“家庭助手”，展示生成中、成功或失败状态 |

不支持发送可执行脚本、HTML 应用或自动播放媒体。文件类型和大小受全局上传策略限制。

### 6.4 回复、引用和提及

- 用户可引用一条消息进行回复。
- 引用区显示原发送者和正文摘要；原消息撤回后显示“原消息已撤回”。
- 首版只支持 `@家庭助手`，不要求成员提及提醒；成员提及可列入后续版本。
- 引用与提及使用结构化字段，不依赖解析显示文本。

### 6.5 编辑与撤回

- 用户可以在发送后 15 分钟内编辑自己的文本消息。
- 编辑后显示“已编辑”，服务端保留修订审计信息，但普通成员不查看完整修订历史。
- 用户可以在发送后 2 分钟内撤回自己的消息；家庭管理员可按治理权限隐藏消息。
- 撤回是状态变更，不物理删除消息行；客户端显示撤回占位。
- 附件消息撤回后立即停止新下载授权，实际文件由保留策略异步清理。
- 系统消息和助手执行结果不能由普通成员编辑。

### 6.6 未读与已读

- 服务端为每位成员、每个会话保存 `last_read_sequence`。
- 未读数按当前最大可见序号与已读序号计算，撤回消息和不计入未读的系统事件应排除。
- 会话处于前台且消息已进入可视区域后，客户端批量更新已读位置。
- 首版不显示逐条“谁已读”，只提供个人未读数。
- 多设备更新采用单调递增规则，旧设备不得把已读位置回退。

### 6.7 草稿和发送状态

- 每个会话在本地保存独立草稿。
- 发送状态包括 `SENDING`、`SENT` 和 `FAILED`；服务端持久化状态不使用 `SENDING`。
- 网络失败允许使用同一 `client_message_id` 重试。
- 切换会话和刷新页面不能意外重复发送。

### 6.8 搜索

首版可不提供全文搜索，但数据模型和 API 不应阻止后续按关键词、发送人、时间和附件类型搜索。若首版纳入搜索，只索引未撤回的文本正文，不索引文件二进制内容。

### 6.9 通知

- 复用家庭通知体系生成离线消息提醒，不为每条消息创建不可控的站内通知记录。
- 用户可为每个家庭设置“全部消息”“仅家庭助手和重要系统事件”或“静音”。
- 当前正在前台查看会话时不发送重复通知。
- 通知预览遵守家庭隐私设置；锁屏通知可仅显示“收到一条家庭消息”。

## 7. 家庭助手和隐私边界

### 7.1 默认行为

- 普通家庭消息不触发模型调用。
- 普通家庭消息不自动写入 Agent `threads`、家庭长期记忆或搜索索引中的记忆类型。
- 家庭助手不能后台持续监听并总结全部聊天。
- 管理员不能替其他成员静默同意把全部聊天交给外部模型。

### 7.2 明确触发

一次 AI 请求只能由以下动作触发：

1. 文本中结构化提及家庭助手。
2. 对一条消息执行“交给家庭助手”。
3. 用户在明确预览上下文后执行“总结这些消息”。

请求需记录触发用户、授权消息范围、使用的模型提供方、请求时间和最终状态。模型输入不得包含未授权附件正文或超出上下文范围的历史消息。

### 7.3 助手产生的事实

助手回复默认只属于聊天记录。若回复中产生值得保存的家庭事实，应进入现有记忆候选审核流程，不能直接成为已确认家庭记忆。

## 8. 信息架构与界面要求

### 8.1 桌面布局

```text
┌──────────────┬──────────────────────────────────┐
│ 家庭消息      │ 家庭群                     设置 │
│ ● 我的家庭  3 │ 妈妈  19:20                    │
│              │ 明天晚饭提前到六点吧             │
│ Agent 对话    │                                  │
│ …            │ 爸爸  19:22                    │
│              │ 好的，我来接孩子                 │
│              │                                  │
│              │              我  19:23          │
│              │              @家庭助手 加到日历 │
│              ├──────────────────────────────────┤
│              │ ＋  输入消息…             发送  │
└──────────────┴──────────────────────────────────┘
```

家庭消息与 Agent 对话在导航和视觉上必须可区分，避免用户误以为所有家庭消息都会交给 AI。

### 8.2 移动布局

- 会话列表与消息时间线使用两级页面。
- 输入框固定在安全区上方，键盘弹出后保持当前消息可见。
- 图片和视频上传支持进度、取消和失败重试。
- 触摸目标不小于常用移动端可访问尺寸，支持屏幕阅读器标签。

### 8.3 空状态和错误状态

- 新家庭群显示欢迎语和隐私说明。
- 断网时显示“等待网络”，已输入内容不得丢失。
- 权限失效时关闭实时连接并返回家庭选择页。
- 附件不可访问时展示文件卡片和明确错误，不显示永久加载状态。
- 助手调用失败时保留用户原消息，并提供重试助手调用的操作。

## 9. 数据模型建议

资源表遵循项目公共字符串 ID 规范，使用整数代理主键和唯一公共 ID。SQLite 与 PostgreSQL 必须提供等价迁移。

### 9.1 `homemind_family_conversations`

| 字段 | 说明 |
| --- | --- |
| `id` | 整数代理主键 |
| `conversation_id` | 公共 ULID，唯一 |
| `family_id` | 关联家庭公共 ID |
| `kind` | 首版固定为 `FAMILY_DEFAULT` |
| `name` | 显示名称，默认“家庭群” |
| `created_by_user_id` | 创建者用户 ID |
| `last_sequence` | 已分配的最大消息序号 |
| `last_message_at` | 最后一条可见消息时间 |
| `created_at`、`updated_at` | UTC 时间 |

约束：首版同一 `family_id` 只能存在一个 `FAMILY_DEFAULT` 会话。

### 9.2 `homemind_family_conversation_members`

| 字段 | 说明 |
| --- | --- |
| `id` | 整数代理主键 |
| `conversation_member_id` | 公共 ULID |
| `conversation_id` | 会话公共 ID |
| `user_id` | Octop 用户整数 ID |
| `last_read_sequence` | 单调递增已读位置 |
| `notification_level` | `ALL`、`IMPORTANT`、`MUTED` |
| `joined_at`、`left_at` | 成员可见期 |
| `updated_at` | UTC 时间 |

家庭成员关系是授权来源；该表保存会话偏好和可见期，不代替家庭成员表。

### 9.3 `homemind_family_messages`

| 字段 | 说明 |
| --- | --- |
| `id` | 整数代理主键 |
| `message_id` | 公共 ULID，唯一 |
| `conversation_id` | 会话公共 ID |
| `sequence` | 会话内严格递增序号 |
| `client_message_id` | 客户端幂等 ID |
| `sender_type` | `USER`、`ASSISTANT`、`SYSTEM` |
| `sender_user_id` | 用户消息发送者；其他类型为空 |
| `message_type` | `TEXT`、`IMAGE`、`AUDIO`、`VIDEO`、`FILE`、`SYSTEM`、`ASSISTANT` |
| `body` | 纯文本正文或结构化内容的可显示文本 |
| `reply_to_message_id` | 被引用消息 ID |
| `assistant_request_id` | 对应 AI 请求，可空 |
| `edited_at`、`retracted_at`、`hidden_at` | 状态时间 |
| `created_at`、`updated_at` | UTC 时间 |

唯一约束：`(conversation_id, sequence)` 和 `(conversation_id, sender_user_id, client_message_id)`。

### 9.4 `homemind_family_message_attachments`

保存附件公共 ID、消息 ID、文件资源引用、原始文件名、MIME、字节数、SHA-256、宽高、时长和创建时间。附件二进制继续由既有家庭资源或专用受控存储管理，表中不得保存任意客户端绝对路径。

### 9.5 `homemind_family_message_revisions`

保存消息 ID、修订序号、旧正文、操作者和时间，用于安全审计。普通成员 API 不返回该表内容。

### 9.6 `homemind_family_assistant_requests`

保存请求 ID、触发用户、会话、触发消息、授权上下文边界、提供方、模型、状态、错误码和时间。不得保存密钥或未经脱敏的模型认证信息。

## 10. API 需求

建议新增家庭领域端点：

```text
GET    /api/families/{family_id}/conversations
GET    /api/families/{family_id}/conversations/{conversation_id}
GET    /api/families/{family_id}/conversations/{conversation_id}/messages
POST   /api/families/{family_id}/conversations/{conversation_id}/messages
PATCH  /api/families/{family_id}/conversations/{conversation_id}/messages/{message_id}
POST   /api/families/{family_id}/conversations/{conversation_id}/messages/{message_id}/retract
POST   /api/families/{family_id}/conversations/{conversation_id}/read
POST   /api/families/{family_id}/conversations/{conversation_id}/assistant-requests
PATCH  /api/families/{family_id}/conversations/{conversation_id}/preferences
```

### 10.1 分页契约

- 消息历史使用基于 `sequence` 的游标分页，不使用 offset。
- 请求参数包含 `before_sequence` 或 `after_sequence`、`limit`。
- 默认返回最近 50 条，服务端最大 100 条。
- 响应包含 `items`、`has_more`、`oldest_sequence`、`newest_sequence`。
- 消息创建响应返回服务端正式消息和 `sequence`。

### 10.2 错误语义

新增错误码至少包括：

- `FAMILY_CONVERSATION_NOT_FOUND`
- `FAMILY_MESSAGE_NOT_FOUND`
- `FAMILY_MESSAGE_FORBIDDEN`
- `FAMILY_MESSAGE_EDIT_WINDOW_EXPIRED`
- `FAMILY_MESSAGE_RETRACT_WINDOW_EXPIRED`
- `FAMILY_MESSAGE_INVALID_ATTACHMENT`
- `FAMILY_ASSISTANT_CONTEXT_FORBIDDEN`

错误信息进入中英文后端 i18n，并同步 Dashboard `apiErrors`。

### 10.3 OpenAPI

所有路由提供明确 `summary`、描述、请求模型和响应模型；非显然字段使用 `Field` 描述。新资源应在 API 元数据中使用或增加可读标签，并检查 `/api/docs`。

## 11. 实时通信协议

### 11.1 连接与订阅

- 优先复用现有 WebSocket 基础设施，但家庭频道与 Agent 会话使用不同的订阅主题和鉴权路径。
- 客户端订阅时提交 `family_id`、`conversation_id` 和最后确认事件序号。
- 服务端在连接建立和成员变更时校验家庭访问权。
- 一个账号多设备可同时在线。

### 11.2 事件类型

```text
family.message.created
family.message.updated
family.message.retracted
family.message.hidden
family.read.updated
family.member.joined
family.member.left
family.conversation.updated
family.assistant.status
```

每个事件包含 `event_id`、`family_id`、`conversation_id`、`occurred_at` 和事件载荷。客户端必须容忍重复事件和未知事件类型。

### 11.3 一致性规则

- 数据库提交成功后才广播消息事件。
- WebSocket 只负责低延迟通知，HTTP 消息历史是恢复真相源。
- 广播失败不能回滚已成功写入的消息。
- 客户端以 `message_id` 和 `sequence` 去重。
- 消息顺序由服务端生成，不采用客户端时间排序。

## 12. 附件和媒体要求

- 上传目的新增 `FAMILY_MESSAGE_ATTACHMENT`，并记录 `family_id` 和上传用户。
- 消息发送前，服务端验证附件已完成、属于同一家庭、属于当前用户可用范围且尚未绑定其他消息。
- 图片生成缩略图；视频可异步生成封面。转码不是首版前置条件。
- 视频和长音频需要 HTTP Range、`206 Partial Content`、`Accept-Ranges` 和 `Content-Range`，避免读取完整文件后再播放。
- 访问 URL 应短期有效或由鉴权端点流式返回，不能产生永久公开链接。
- MIME 不能只信任客户端声明；至少结合扩展名与内容探测，并使用 `nosniff` 和安全的 Content-Disposition。
- SVG、HTML 等主动内容不能在同源上下文中无沙箱执行。
- 删除、撤回、成员退出和家庭删除时，附件生命周期应有明确引用计数或清理任务。

## 13. 安全与隐私要求

### 13.1 安全控制

- 所有通信使用 TLS；认证沿用现有 JWT 机制。
- 消息正文、文件名和用户提供的富文本按不可信输入处理。
- Markdown 渲染必须禁用原始 HTML 和危险 URL 协议。
- 发送消息、上传、下载和助手调用设置用户与家庭级速率限制。
- 文件扫描失败时采用明确策略：阻止高风险类型，普通文件标记扫描状态。
- 日志不得记录完整消息正文、附件内容、访问令牌或本地绝对路径。
- 管理审计与聊天内容访问分离；运维日志默认只记录 ID、大小、状态和耗时。

### 13.2 隐私控制

- 新家庭群首次进入时说明谁能看到消息、何时会调用 AI。
- 调用外部模型前展示提供方和发送范围；遵守现有家庭外部处理设置。
- 家庭导出应可选择包含消息元数据、正文和附件，默认不静默包含大体积原始媒体。
- 家庭删除流程必须覆盖消息、附件、已读位置、助手请求和搜索索引。
- 管理员查看审计记录不等于获得已删除正文的常规浏览入口。

## 14. 非功能要求

### 14.1 性能

- 最近 50 条纯文本消息在正常家庭宽带下应快速呈现，不等待全部媒体下载。
- 发送文本消息的服务端持久化与广播目标 P95 小于 500 毫秒，不包含客户端网络延迟和助手生成时间。
- 消息列表采用虚拟化或等效方案，加载 5,000 条历史消息后不应导致明显输入卡顿。
- 附件上传和播放不得把整个大文件一次性载入服务端或浏览器内存。

### 14.2 可靠性

- 重复提交不产生重复消息。
- 服务重启后消息历史、附件关联和已读位置不丢失。
- WebSocket 中断后能够通过 HTTP 恢复全部已提交消息。
- 助手失败不影响人类消息的发送和读取。

### 14.3 可访问性和国际化

- 所有用户可见文本进入中英文 i18n。
- 键盘可完成会话选择、消息输入、发送、回复和附件操作。
- 状态变化提供屏幕阅读器可理解的提示，不只用颜色表达失败或未读。
- 用户可见时间使用服务端时区，数据库持久化 UTC。

### 14.4 可观测性

指标至少包括：消息创建成功率和延迟、实时广播延迟、活跃连接数、重连次数、附件上传失败率、Range 请求量、助手请求成功率和延迟、权限拒绝数。指标标签不得包含消息正文、文件名或高基数的用户私密信息。

## 15. 数据保留、删除和治理

- 默认消息保留期由产品策略确定；首版可采用持续保留，但必须预留家庭级策略字段。
- 用户退出家庭后失去访问权，其已发送消息默认保留并继续显示当时昵称快照，避免破坏对话语义。
- 用户账号删除遵守现有账户删除策略；必要时将发送者显示为“已注销成员”。
- 撤回消息的正文和修订历史只在安全审计保留期内保存，之后进行不可逆清理。
- 家庭管理员隐藏消息必须填写预定义原因，行为写入家庭审计日志。
- 法律或合规删除请求必须级联清理搜索索引、缓存、缩略图和孤立附件。

## 16. 兼容性和架构边界

- HomeMind 可以依赖 Octop 的认证、上传、WebSocket 和通用基础能力；Octop Core 不得反向导入 `homemind`。
- 家庭消息领域规则放在 `src/homemind/infra/`，HTTP 路由保持薄层。
- 家庭消息 repo 放在 HomeMind 数据库 repo 区域，不从 router 直接拼写 SQL。
- 不复用 Agent `threads` 保存人类群聊，也不把家庭成员伪装成 Agent。
- Dashboard 只能通过 `/api` 和实时协议访问消息，不直接依赖 Python 模块或数据库结构。
- 数据库变更同时提供 SQLite 和 PostgreSQL 迁移，并更新 HomeMind schema 版本测试。

## 17. 分阶段交付

### 阶段 0：契约和风险冻结

- 确认成员可见期、删除保留、编辑与撤回窗口。
- 冻结数据模型、API、WebSocket 事件和错误码。
- 明确附件复用方案以及 Range 支持范围。
- 输出威胁模型和隐私评审结论。

### 阶段 1：文本群聊基础

- 默认家庭群幂等创建。
- 文本消息创建、历史分页和实时广播。
- 会话列表、消息时间线、草稿与失败重试。
- 家庭权限校验和基础审计。

### 阶段 2：未读、回复和消息治理

- 已读游标、未读计数和多设备同步。
- 引用回复、编辑、撤回和管理员隐藏。
- 家庭通知偏好和离线通知。

### 阶段 3：附件和媒体

- 图片、音频、视频和文件上传。
- 缩略图、播放器、鉴权下载和 Range 请求。
- 断点续传、孤立附件清理和媒体测试。

### 阶段 4：家庭助手

- `@家庭助手` 和“交给家庭助手”。
- 上下文授权预览、调用审计和失败恢复。
- 高风险动作审批以及记忆候选流程。

### 阶段 5：质量和后续客户端准备

- 大历史性能、断网恢复、多设备和跨平台测试。
- API 文档、运营指标、备份恢复和家庭导出。
- 稳定移动端可复用协议，不在本阶段承诺原生客户端交付。

## 18. 验收标准

### 18.1 核心验收

1. 两个同一家庭的用户可在不同浏览器中实时收发文字消息。
2. 非家庭成员无法列出会话、读取消息、订阅事件或下载附件。
3. 相同 `client_message_id` 重试十次只生成一条消息。
4. WebSocket 断开期间发送的消息在重连后通过历史接口完整恢复且不重复。
5. 多设备已读位置只前进不后退，未读数一致。
6. 成员被移除后，其现有连接不能继续收到家庭消息。
7. 图片、音频、视频和文件可发送、预览或下载；大视频拖动播放使用 Range 请求。
8. 撤回后普通接口不再返回原正文，附件不能继续获取新的访问授权。
9. 普通聊天不产生模型调用；只有明确触发家庭助手时才发送限定上下文。
10. 助手调用失败不产生重复的人类消息，也不阻断家庭群继续通信。
11. 所有用户可见文案具备中英文翻译，时间显示遵循服务端时区。
12. SQLite 和 PostgreSQL 行为一致，Linux 与 Windows 测试通过。

### 18.2 建议验证命令

实现阶段按改动补充定向测试，最终交付至少执行：

```bash

cd dashboard && npm test -- --run
cd dashboard && npx tsc -b
make all
```

## 20. 发布与回滚

- 使用功能开关按家庭或部署实例灰度启用。
- 首次启用时幂等创建默认会话，不要求离线批量创建所有家庭会话。
- 数据库迁移必须向前兼容旧版本应用读取现有非消息功能。
- 回滚应用版本时保留新表，不自动删除消息数据；关闭功能入口和事件订阅即可。
- 灰度阶段监控权限拒绝异常、重复消息率、广播延迟、附件失败和助手误触发。

## 21. 待产品确认事项

以下决策应在阶段 0 完成，不影响本需求的总体架构：

1. 消息默认保留期限是永久、按年还是由家庭管理员配置。
2. 被移除成员重新加入后，是否可以查看其离开期间的历史消息。
3. 编辑窗口 15 分钟、撤回窗口 2 分钟是否符合目标用户预期。
4. 管理员是否拥有隐藏消息权限，以及需要提供哪些原因选项。
5. 锁屏通知默认显示正文还是只显示消息提示。
6. 家庭助手默认使用多少条上下文，以及用户是否可在每次调用前调整范围。
7. 首版是否必须包含全文搜索，还是在数据规模验证后交付。
8. 音视频文件的单文件上限和家庭总存储配额。
